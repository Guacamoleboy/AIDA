# Security in an AI-supported customer flow

Security is especially important in the Engestofte Gods project because the solution will handle customer accounts, contact details, wedding plans, dietary requirements and communication between customers and Owner.

### Security starts with boundaries

An agent should only receive the repository context and permissions needed for its ticket. A ticket must state what may be changed, what is out of scope and when the agent should stop. Repository instructions are useful, but important boundaries should also be enforced through authentication, authorization, code review and deployment configuration.

### Secrets and external AI services

OpenAI keys, database credentials and other secrets must never be hardcoded or committed. They belong in environment configuration or a proper secret-management solution.

The AI-flow also creates a data-protection question. The school prototype stores the raw draft in `localStorage` before login, but this is only a documented prototype decision. It is not a production approval to store sensitive data this way. A production solution would require a proper assessment of GDPR, retention, access, hosting and the data sent to an external AI provider.

### Authorization is not a prompt instruction

The customer, primary contact person, additional contact persons, Owner and Staff have different rights. Those rights must be enforced by the application and backend, not only described in an AI prompt.

Owner has full access. Staff may see relevant operational information such as dietary requirements, but not Messenger conversations or direct customer identifiers. Event data and Messenger must also remain isolated between different events.

### Human control and AI transparency

The AI may collect information, identify uncertainty and suggest relevant extras. It must not invent prices, promise availability or make the final booking decision. Owner remains responsible for approval, commercial decisions and customer communication.

Customers should be told when they are interacting with AI. AI-generated suggestions and internal drafts must be clearly separated from approved human decisions. Source references and uncertainty markers make the system easier to review.

### My conclusion

Security is not a final feature. It is a set of decisions about permissions, secrets, data minimisation, external services, input validation and human review. I will continue using agents, but I will keep control of the boundaries and require the implementation to follow the specification instead of trusting generated code automatically.
