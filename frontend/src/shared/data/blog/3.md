***Research, understanding and.. PROBLEMS!***

Apparently updating knowledge cards was harder than expected. Dify haven't really thought of that. I guess.

I researched and found out there's basically no information about it online. So I sat down and read the Dify API Docs about knowledge cards. There's a update-by-text endpoint which allows you to update knowledge card text by simply using an endpoint. The endpoint takes 2 unknown ids though...

It needs:

> Knowledge Base ID\
> Knowledge Card ID (Multiple)

Getting the Knowledge Base ID was fine. It wasn't an issue. I then used the Knowledge Base ID to locate the remaining IDs. The Knowledge Card IDs. There are multiple. I could probably have found them in a smarter way but this is how I did it.

I then spent about 1-2 hours thinking untill my brain hurt. Came up with a bunch of different solutions. 

**The one I went with:**

Dify knowledge cards are NOT dynamic. For some reason Dify API Docs said they re-index and updates it when update-by-text was used. This gave me a headache untill I really understood it. The Knowledge Card IDs don't update. The context and the chunks update. Not the actual ID. The ID is the same. Always. So I could simply create a dify.json doc with the .md name and the ID in the root of my repository and use it for Github Projects. I now have the Knowledge Base ID and the Knowledge Card IDs.. I just need to find out which file has changed. So I fetch on level 2 using dify.yml workflow which allows me to use git diff. If a knowledge card has been changed under RAG/knowledge it simply uses DIFY_API_KEY from Github Secrets and the ID from dify.json to send a curl POST request to update-by-text with the upate.
