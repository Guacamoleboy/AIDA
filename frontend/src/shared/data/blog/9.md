# Starting a project.

After the presentation from Engestofte Gods, it was time to start thinking about a project. The obvious idea was to make a solution for their Christmas market.

The Christmas market is currently managed with PDF files, emails and Trello. Lise receives a very large number of emails and has to keep track of where the different vendors should be placed. A digital booking solution with a map of the market could probably reduce a lot of that work.

I then looked at projects made by students from previous years. I noticed that several students had already created solutions for the Christmas market. Even though Engestofte Gods has not used those solutions yet, I did not feel very motivated to make the same type of project again. I would rather investigate another problem where I can create something more specific and hopefully more useful.

### A possible Trello integration

My current idea is to create a small system around Trello. Johan already uses Trello as his main planning tool, so replacing it would not make much sense. The real issue is that information is repeated across several cards and that changes have to be made manually in multiple places.

I could make a **source of truth** for an event. The information could be entered once and then used to create or update the relevant Trello cards, checklists and perhaps email drafts through the Trello API. If a wedding has a change in the number of guests or the food requirements, Johan should not have to search through eight different cards to update the same detail.

The system could also check for missing information before an event is considered ready. For example, it could make sure that food, seating, schedule and contact information are all present. It would not replace Johan's decisions. It would simply help him keep the information consistent.

### Why this could be useful

Johan lives some distance from the estate and spends a lot of personal time handling the business. A solution that saves a few minutes in one place might not sound important, but repeated across every wedding and every change it could become a real improvement.

The solution should also respect that Trello has a mobile application. Johan and the employees should still be able to use the tool from wherever they are. My system would act as a layer around Trello instead of forcing them into a completely new workflow.

There are many things I still need to investigate. I need to understand the Trello API, authentication, permissions, rate limits and what kind of data can safely be synchronised. I also need to talk to the company before deciding whether this is actually the right problem to solve.

### Project direction

I do not have a final project idea yet, and that is okay. The first project decision should not be based on what is fastest to code. It should be based on a real need and on whether I can build something that the company could actually understand and use.

For now, I will explore the Trello integration idea. It combines AI-driven development with a concrete business problem and gives me a reason to work with an existing API instead of creating another isolated demo application.

The next step is to turn the idea into a proper specification. Then I can see if the problem is small enough for the course and whether the solution can be tested properly.
